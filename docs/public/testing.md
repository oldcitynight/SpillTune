# Tests and CI status

Run the portable CPU check from a working copy of the current candidate using existing compatible dependencies:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
python tools/portable/ci_cpu.py --output ../ram-vram-cpu-check
```

The output directory must be new. Before copying any files, the script validates the original input test tree against its reviewed inventory: a new test missing from both allowlist and inventory cannot silently disappear from the build. The copied inventory must be byte-identical, and original and staged test sources remain checked through completion. The script then copies only allowlisted files, scans that build tree, builds its own wheel and sdist without dependency resolution, and verifies the sdist includes the inventory, audit tools and complete test sources. License-material checks run before build and against required material bytes in the built wheel/sdist; they retain the selected GPL target and pending-rights boundary. It installs the wheel with `--no-index --no-deps` into a new target. Tests and CLI commands run outside the source import directory; source/wheel/installed runtime hashes are checked. The actual collection and execution processes attest every loaded project module inside the requested installed package tree; the parent checks the recorded paths again using path containment, including rejection of prefix-lookalike directories. Tiny CLI inspect/train/resume uses configurations from the copied build tree, and `pip check` checks the reused environment. Logs and reports remain private local outputs.

## Exact discovery and actual execution

[`tests/cpu-inventory.json`](../../tests/cpu-inventory.json) is the reviewed expectation, not a value regenerated by CI. It lists exact root-relative parametrized nodeids and SHA256 hashes of the test tree, test helpers/conftest, pytest configuration and portable runner/auditor. The inventory JSON itself is excluded from its own content hashes. To display its expected count without an outdated constant:

```bash
python -c "import json; print(len(json.load(open('tests/cpu-inventory.json'))['nodeids']))"
```

The portable entry clears `PYTEST_ADDOPTS`, `PYTEST_PLUGINS`, `PYTEST_CURRENT_TEST` and inherited import paths, disables third-party plugin auto-loading, overrides configured addopts and fixes the test root and command arguments. It first runs an independent collect-only subprocess. Discovery must be nonempty and match every expected nodeid exactly, without duplicates, deselection, collection skips or errors. Changed/missing/extra test sources require explicit inventory maintenance and fail before execution.

A second subprocess executes the full suite. For every expected nodeid, the event ledger must contain exactly one passed setup, call and teardown, without skip, xfail/XPASS, duplicate phases or unexpected identities. The parent validates this ledger and the final subprocess exit code before producing an accepted audit; a hook-written provisional ledger or JUnit count alone is never success. JUnit is an additional consistency check. Both subprocess ledgers bind the initially read inventory SHA256; the parent rechecks that identity after each subprocess and before its final report, rejecting inventory edits during the run. Reports retain the pytest version and loaded plugin names. Regression cases exercise lost/replaced tests, zero tests, filtering, environment contamination, stale sources, missing/duplicate calls, skip/xfail/XPASS, collection errors and nonzero final exits.

These checks detect accidental omission and filtering within a reviewed code/plugin trust boundary. They do not defend against malicious test code or plugins forging pytest events. They do not establish every model, dependency version or long training regime.

## Deliberate inventory maintenance

After reviewing intentional test or audited tooling/config changes, refresh explicitly from a working copy with compatible dependencies:

```bash
python tools/portable/suite_audit.py refresh --output tests/cpu-inventory.json --force
```

Review the nodeid and source-hash diff alongside the code change. Added, removed or renamed tests must be intentional. `--force` is needed to replace an existing inventory; failed collection does not replace it. CI never runs this refresh command. Include the reviewed inventory, test changes and updated allowlist in the next candidate, then run the actual portable entry again.

## Environment and historical validation

The manual `.github/workflows/cpu.yml` declares a Linux Python3.14 CPU job that provisions external dependencies and invokes this portable entry. It has not run remotely. Local CUDA-enabled Torch executing CPU tests does not validate the separate CPU wheel, a clean resolver run, Python3.11 or other operating systems. The portable CPU entry installs no third-party dependency and starts no GPU or pretrained-source job. Separately budgeted real-source load/validation evidence is required for performance claims.

The full suite covers native-reference gradients/updates, accumulation, state recovery, aliases, codecs, adapter schemas, memory lifecycle and resource gates. The exact release receipt states which tests executed; collection alone is not a full-suite PASS. Native Windows/MSI and hosted CI need their own execution evidence.

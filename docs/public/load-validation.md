# Bounded full-storage validation

The 0.0.1 change increases group-aligned validation work per Python loop, while retaining a bounded scratch size no larger than the existing encoder chunk. All stored scales, codes, tail padding and FP32/BF16 decoded range checks still execute over every element; schema and frozen-contiguous checks remain. Raw finite scans use the existing implementation. Encoding, storage identity hashing, pinned packing, device decoding, optimizer and checkpoint protocols are unchanged.

Validation uses 2048 groups per chunk: each decoded FP32 array is at most 1 MiB, with several arrays and conversion/mask temporaries potentially alive together. This is not a 1 MiB total-process scratch claim. Equivalent predicates remove repeated scans: the full decoded BF16 conversion/finite check rejects both FP32 nonfinites and BF16 overflow; an integer code decoded from the validated bit format is always finite, while its reserved-code test remains. FP8 still checks its nonfinite code patterns. Encoder byte calculations are identical; only its redundant decoded-FP32 finite pass is removed under the same BF16 implication.

Use CPU inventory tests to check corrupt payload/scales at the beginning, either side of chunk boundaries and the end, including finite FP32 products that overflow BF16, plus the existing independent bit/reference tests. Do not infer correctness solely from lower memory or successful training.

The local real-source protocol uses the same original 27B Qwen3.5 source, internal int4-sym-g128/BF16, rank2/alpha4, accumulation2 and two short synthetic sequences (8 and 6 tokens). An exploratory cProfile run is excluded from benchmark comparisons. Unprofiled old/new runs record source load, complete session initialization, actual validator totals, both updates, checkpoints/export, RAM/PSS/swap and CUDA allocated/reserved plus sampled physical GPU use. A separate old/new/new/old comparison validates the same already-resident pinned matrices in real linear layer0 and full-attention layer3. Include its complete diagnostic overhead separately.

Fresh processes do not imply equally cold files. No global cache eviction is part of this protocol. Record page faults, actual read bytes and cgroup reclaim/pressure; report initialization/end-to-end wall times as cache-sensitive observations unless comparable conditions are demonstrated. Resident-validator comparisons support only that workload. Preserve all required integrity checks and compare full stored identities, optimizer/gradient/update/RNG fields and exports; resume checkpoint1 in a new process and compare update2 exactly. The local two-block HF VJP check does not establish an independent full-model BF16 trajectory, held-out quality or long training.

Keep temporary own-job memory/swap/deadline guards and external cleanup confirmation. No physical OOM stress, dependency installation, new model acceptance or native low-bit GEMM is added. Results and source/artifact hashes belong in the local batch evidence, not machine paths inside this candidate.
